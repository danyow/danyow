# 电话语音 Agent 每日观察

这是已有资讯站的第二个独立栏目。每日研究任务由用户的定时执行环境触发，本文件不是调度器，不含私人投递配置。

## 研究目标

发现能通过普通手机电话控制个人 Agent 的框架、论文和真实案例：主动来电汇报、允许拨入和插话、执行口头命令、挂断后继续任务、跨通话保存记忆、需要时回拨。24小时在线表示服务待命，不要求24小时通话或监听。

优先手机号码的真实呼入/呼出。App或网页语音需明确标为替代路线。关注中文、常驻运行、断线恢复、工具执行、身份验证、敏感动作确认和操作记录。号码地区、个人申请资格及费用需分别核实，不能用“支持中文”代替“能拨中国大陆手机”。仅研究，不实际拨号或执行案例中的命令。

来源遵循 [共同来源规范](../research/SOURCE_POLICY.md)：每日分别检查国际官方/开源、国内/中文、论文、X公开线索，末尾报告真实覆盖情况。初次建立基线，随后只报实质增量并回看7天。不要变成泛语音合成新闻或电销榜单。

## 阅读格式

正文通常500至800字、1至3条重点，分别讲新在哪、离电话助手还差什么、现在能否试用。必要术语补一句白话，作者主张与已验证事实分开。无重大更新可以80至150字。来源紧跟条目，不反复铺技术参数。邮件仅短摘要和链接，不重复长文。

## 原稿与网页

- 原稿：`voice-agent-watch/reports/YYYY/MM/YYYY-MM-DD.md`。
- 网页：`/danyow/voice-agent-watch/reports/YYYY-MM-DD/`。
- 原始MD、月份索引、近期索引和版本回执：栏目下的 `raw/`、`index/`、`receipts/`。
- 格式沿用 `ai-engine-watch/bridge/Core.gs` 的 JSON 头部和纯Markdown约定；标题为“电话语音 Agent 每日观察”。固定字段为 schema/date/timezone/title/revision/publication/review_status/summary/events；schema=1、timezone=Asia/Shanghai、publication=publish、review_status=generated。日期、事件字段及枚举沿用共同校验，禁止提交私人资料或未核验历史导入。
- 先验证并计算原稿SHA-256，再只提交本栏目的MD。已有同稿不重提，更正增加revision，条件更新避免覆盖他人提交。历史查询先读本栏目索引，不读取全部HTML。

## 发布与发送

由现有 Actions 同时构建两个栏目。任务提交后查询与该原稿匹配的构建和Pages部署，在单次运行预算内间隔检查；后续提交接替构建时，须确认同一原稿仍被包含。公开日期页、raw和回执的日期、修订号及SHA-256一致后才发链接。

通过用户私有配置的Gmail和pushplus地址分别发送，两端主题一致：`电话语音 Agent 每日观察｜MM-DD`，例如 `电话语音 Agent 每日观察｜09-12`。标题在前，月日补零的短日期在最后，不加机器前缀、不显示年份。日期取本份报告的北京时间日期，而不是补发当天。修订、补发和异常状态放在标题后的括号中、日期之前，例如 `电话语音 Agent 每日观察（发布未完成）｜09-12`。

短日期只用于邮件标题。原稿元数据、文件名、网页链接、索引和回执仍使用完整 `YYYY-MM-DD`；去重标识 `VOICEAGENT-YYYY-MM-DD-rN` 和原稿哈希保留在邮件末尾低强调的一行。去重兼容旧 `[VOICEAGENT-DAILY]`、`[VOICEAGENT-PIPELINE]` 主题和新主题，以栏目、完整日期、修订和哈希确认，不只搜索旧前缀或根据月日判断跨年记录。仅改变标题样式不重发旧邮件，也不修改历史原稿。

失败只发简短异常说明，不发坏链接或冒充完成；保留状态，下次实际运行恢复。网页发布不等于邮件已发出，邮件发出不等于手机已收到。
