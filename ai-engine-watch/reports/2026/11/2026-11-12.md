# AI 引擎日报｜2026-11-12

今天的有效增量集中在交付与调试：一边把多引擎发布收拢，另一边补齐联机恢复和性能定位工具。

## **Genex 0.1.38：多引擎发布集中到一个窗口**

Genex 0.1.38 为 Unreal、Unity、Godot 与 Roblox 简化设置，并把各平台发布、批量更新、断点续传、速度和剩余时间放到统一窗口；Unreal 网页构建还增加托管体积检查。它适合代理完成游戏后持续上传大包，但这是厂商发布说明，尚未看到独立可靠性测试；Linux 包因 GitHub 构建机故障暂缓，不能视为全平台齐备。[发布说明（11-12）](https://github.com/genex-games/genex-desktop/releases/tag/v0.1.38)

这次的实用点是失败后不必从头上传，开发者也能看见字节数、速度和预计剩余时间；多人房间查询还会跨区域寻找已有房间。对频繁改包的代理流程，这比单次“发布成功”更接近可恢复交付。不过统一窗口仍由 Genex 服务协调，版本说明没有公开大包断线、跨区延迟或多次恢复后的完整测试数据。

## **Origin Engine：联机房间会恢复，热点也能追到源码**

Origin Engine 的锁步联机在中继断开后会指数退避重连，成功后让玩家取回原席位；重试窗口为 30 秒，但断线期间已发送的数据仍会丢失。另一提交给原生宿主加入 CPU 剖析，可输出 Chrome/VS Code 可读文件，或带源码位置的 Markdown 热点与调用树。两项代码均公开，适合代理自动回归和定位慢帧，不过当前只是仓库实现，尚未经过跨网络、长局与大型项目复测。[重连提交（11-12）](https://github.com/originai-game/origin-engine/commit/a7e458ea7de443e3900876f9909942bdacdf7ad5)｜[剖析提交（11-12）](https://github.com/originai-game/origin-engine/commit/94289db35137305900d2ac3dc892239e7670ed5d)

重连从约 250 毫秒开始，逐步放慢到最多 4 秒一次，避免短暂故障时密集请求；它恢复的是连接和席位，不会补发断线期间的输入，因此游戏逻辑仍要处理缺帧与状态差异。剖析器目前只面向原生宿主，但 Markdown 输出便于代理直接读取热点函数、调用路径和源码位置，再生成有依据的优化修改。

我的判断：AI 原生引擎的差异化正从“能生成”转向“能恢复、能观测、能重复发布”，但这些工程承诺仍要用真实项目检验。
